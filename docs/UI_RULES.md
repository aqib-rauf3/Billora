# 🖥️ Billora UI Rules

> Version: 1.0

---

# Purpose

This document defines the UI standards for the entire Billora application.

Every screen, page, section, component, and interaction must follow these rules.

Consistency is more important than creativity.

---

# Core Principles

Every interface should be:

- Clean
- Premium
- Minimal
- Modern
- Fast
- Accessible
- Responsive
- Professional

Never create generic SaaS layouts.

Always follow the design-reference folder.

---

# Layout System

Every page should use a consistent layout.

Maintain proper visual hierarchy.

Use generous whitespace.

Avoid clutter.

Content should never feel cramped.

---

# Container Rules

Use one consistent container width across the project.

Maintain equal left and right spacing.

Do not allow random page widths.

---

# Spacing System

Use a consistent spacing scale.

Never use random spacing values.

Maintain consistent spacing between:

- Sections
- Cards
- Buttons
- Inputs
- Tables
- Navigation
- Icons

Whitespace is part of the design.

---

# Grid System

Use responsive grids.

Desktop:

Multiple columns where appropriate.

Tablet:

Reduce columns naturally.

Mobile:

Single-column layout unless another layout improves usability.

---

# Typography Rules

Headings should:

- Be bold
- Create hierarchy
- Be easy to scan

Body text should:

- Be readable
- Have comfortable line spacing
- Never appear compressed

Avoid excessive font sizes.

---

# Hero Section

Hero must immediately communicate:

- Product value
- Brand quality
- Primary call-to-action

Hero should include:

- Clear headline
- Supporting description
- Primary CTA
- Secondary CTA
- Product preview

Avoid oversized text without purpose.

---

# Navigation

Navigation should be:

- Sticky
- Simple
- Responsive
- Easy to scan

Desktop:

Horizontal navigation.

Mobile:

Collapsible navigation.

---

# Cards

Cards should:

- Feel lightweight
- Have consistent padding
- Use subtle borders
- Use soft shadows

Hover state should improve depth.

Never overuse shadows.

---

# Buttons

Buttons should communicate hierarchy.

Primary Button

- Strong emphasis

Secondary Button

- Less emphasis

Danger Button

- Reserved for destructive actions

Hover effects should be smooth.

---

# Forms

Forms must:

- Be easy to complete
- Clearly indicate required fields
- Show validation messages
- Display loading states

Labels should always be visible.

---

# Tables

Tables should:

- Be easy to scan
- Have proper spacing
- Support responsive layouts
- Highlight important information

Avoid dense tables.

---

# Dashboard

Dashboard should prioritize:

- Quick insights
- Clear navigation
- Fast actions

Widgets should remain consistent.

---

# Icons

Use one icon family.

Icons should:

- Match typography
- Be visually balanced
- Support content

Avoid oversized icons.

---

# Images

Images should:

- Be optimized
- High quality
- Responsive

Avoid decorative images without purpose.

---

# Empty States

Every empty state should include:

- Clear explanation
- Helpful illustration (if appropriate)
- Call-to-action

Never leave blank screens.

---

# Loading States

Every async action should display:

- Skeleton loaders
- Progress indicators
- Loading buttons

Avoid layout shifts.

---

# Error States

Errors should:

- Explain the issue
- Suggest recovery
- Remain visually calm

Avoid technical error messages for users.

---

# Success States

Successful actions should provide clear confirmation.

Use subtle animations where appropriate.

---

# Responsive Rules

Every page must work perfectly on:

- Mobile
- Tablet
- Laptop
- Desktop
- Large displays

No horizontal scrolling.

---

# Accessibility

Maintain:

- Keyboard navigation
- Visible focus states
- Good contrast
- Semantic HTML
- ARIA attributes where required

Accessibility is mandatory.

---

# Performance

Do not sacrifice performance for visual effects.

Prefer lightweight components.

Optimize rendering.

Avoid unnecessary re-renders.

---

# Reusability

Before creating a component:

- Check existing components
- Reuse whenever possible
- Keep APIs simple
- Avoid duplicate implementations

---

# Design Consistency

Every page should feel like part of the same application.

Maintain consistency in:

- Typography
- Colors
- Buttons
- Cards
- Forms
- Icons
- Layout
- Motion

---

# Final Rule

When unsure about a UI decision:

1. Follow CLAUDE.md
2. Follow the design-reference folder
3. Maintain consistency
4. Prefer usability over decoration
5. Build production-ready interfaces
